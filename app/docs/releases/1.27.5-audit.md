# 1.27.2–1.27.5 发布核对：移除不可用的微博辅助页

日期：2026-10-21（Asia/Shanghai）。最终版本：**1.27.5**，已部署原站点并核验。

## 触发原因

用户打开编辑器里的「登录微博并读取」，页面显示「微博辅助页暂不可用」，要求清掉。

## 结论先说

该功能已彻底移除。过程中有三次判断错误，都记录在此，不做美化：

1. **1.27.2 只删了源码和路由**，以为文件就不在了。实际 `COPY server/ /app/server/` 只做新增和覆盖，**不会删除**旧镜像层里已存在的文件，`server/pages/weibo-session.js` 一直被继承下来。
2. **1.27.3 声称已从镜像移除**，这个说法是错的。它确实删了宿主机的 `/opt/shn48/server/pages`，但镜像构建仍以旧镜像为底，文件仍在。
3. **1.27.4 才真正清掉**（`RUN rm -rf /app/server/pages`，已用 `docker run` 直接核对镜像内路径不存在），但该版构建时本地打包产物仍是 1.27.3，导致运行的 1.27.4 镜像内部版本为 1.27.3，健康接口显示 1.27.3，脚本按预期判为「版本不符」并回滚。
4. **1.27.5 是最终版本**：先用版本脚本构建 1.27.5 产物与清单，再以在线 1.27.4 为基础重建，镜像内 VERSION 与标签一致。

## 代码变更

- 删除 `server/pages/weibo-session.js`、`staging/weibo-session-helper.html` 与 `server/index.js` 中该路由注册。
- 编辑器移除「登录微博并读取」入口；昵称识别失败恢复为简洁提示（手填或留空保存）。
- `/weibo-session` 保留一个 404 守卫，返回「该功能已移除」，避免旧链接静默回落成 48tools 外壳页（此前 200 返回首页，看起来像坏页面）。
- 回归断言：旧地址必须 404、不得引用模块、`server/pages` 目录不得存在。

| 1.27.2 | 删源码、删路由、前端去入口 | 上线成功，但镜像内仍有残留文件 |

| 1.27.4 | 构建时 `RUN rm -rf /app/server/pages` | 首次上线因版本不符自动回滚；镜像内容已干净 |

发布过程中所有失败都停在切换前或自动回滚，**生产始终可用**，未执行任何无范围 prune，未删除数据、录像、配置、凭据或回滚镜像。
