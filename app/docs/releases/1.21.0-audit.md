## 为什么有这一版

1.20.0 上线后确认「关注」的方向做错了：它实现的是**本地监视名单**（点亮星标只让后台轮询该房间消息），而不是口袋48账号的关注关系。由此暴露出三个问题：

1. **无法新增关注**。房间列表接口返回的就是**已关注的人**（实测 30 条），列表里不存在未关注的人，所以永远加不上新关注。
2. **「关注」没有实际意义**。点关注只是让页面持续拉消息，与自己点开房间再拉一次没有区别。
3. 因此 1.20.0 的 `pocket48_follows.json` 持久化、30→50 上限、首次关注自动轮询这一整套机制**失去意义，全部移除**。

本轮改为：左侧列出**全站 531 位成员**，直接在这里关注/取关**真实的**口袋48账号。

## 接口来源与实测

来自上游 `duan602728596/48tools`（`packages/48tools/src/services/48/index.ts` 的 `requestFriendshipAdd`）与本地参考实现 `research/pocket48-cli/src/main/services/pocket-service.js`，两者在关注/取关路径上完全一致，并已对线上账号实测：

| 接口 | 用途 | 实测结果 |
| --- | --- | --- |
| `POST /user/api/v1/friendships/friends/id` | 读取已关注成员 ID | `200 success:true`，返回 **41** 个 ID |
| `POST /user/api/v2/friendships/friends/add` | 关注 | `200 success:true`（对已关注者幂等调用亦成功） |
| `POST /user/api/v2/friendships/friends/remove` | 取关 | `200 success:true`（对 id `0` 亦返回成功，即幂等） |

两个关键细节：

- **`toType: 1` 是必需参数**。缺它时上游返回 `缺少请求参数`（注意 HTTP 状态仍为 `200`，只有 body 里 `success:false`）。首次探测因只带了 `toSourceId` 而失败，补齐后成功。
- `friends/id` 返回 **41** 个，**多于**房间列表的 30 个 —— 房间列表看不到的成员也在关注集合内。所以关注集合才是权威来源。

已确认**不存在**的路径（均返回 `404`，不要再去试）：`friendships/friends/list`（v1/v2）、`friendships/friends/del`（v1/v2）、`friendships/friends/delete`、`friendships/friends/cancel`、`friendships/unfollow`。

### 测试发现并修复的真实缺陷

1. **未登录时请求会逃逸到线上**。`/friendships/*` 四个路由起初没有登录闸门，`GET` 在无 token 时会以**匿名身份**发往口袋48并返回 `缺少请求参数`，而不是干净地拒绝。现已全部加 `requireToken`，未登录直接 `409`，并补了「未登录时不发出任何关注请求」的断言。
2. **复用构建会残留已删除文件**。`Dockerfile.release` 用的是 `FROM shn48-shn48:1.20.0` 叠加 `COPY server/ /app/server/`，而 **`COPY` 到已存在目录是合并语义**，不会删除基线里多出来的文件。实测 1.21.0 镜像里**仍然带着已删除的 `monitor.js`**（也即 1.20.0 镜像曾把 1.19.0 的残留一并带下去）。已改为先清理源码子树再拷贝，同时**保留 `/app/server/node_modules`**（依赖装在 `/app/server` 内，27 MB，直接 `rm -rf /app/server` 会连依赖一起删掉并构建出坏镜像 —— 这一点已实测确认后规避）。

   修复后复核：镜像内 `monitor.js` **不存在**，`node_modules` 保留 **102** 个包，pocket48 模块数 **16**，cv2/PIL 断言通过。

### 与本次改动无关的既有失败

`server/test/*` 全量在本机为 15 个失败（`spawn ffprobe ENOENT`、`spawn /opt/asr-venv/bin/python ENOENT` 等），`client/test/pocket48-login-ui.test.js` 失败（1.17.9 体检已记录的 `AutoRecord` 登录页 401 重定向预存缺陷），改动前后表现一致，均属环境或既有问题。
