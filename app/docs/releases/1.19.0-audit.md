## 镜像构建

沿用历次发布验证过的 **reuse 构建**（`FROM shn48-shn48:1.18.0` 叠加新 `server/` + `client/dist/`），
原因是服务器无法访问镜像仓库拉取基础镜像。Dockerfile 内含 `cv2` / `PIL` 断言，防止在缺少
封面渲染运行时的基础镜像上静默发布。

## 回滚方式

保留 1.18.0 镜像（`sha256:75828a6a…b228f`）与 compose 备份 `docker-compose.yml.pre-1.19.0`：

```bash
cd /opt/shn48
cp docker-compose.yml.pre-1.19.0 docker-compose.yml   # 或 sed 回 1.18.0
docker-compose -f docker-compose.yml -f docker-compose.public.yml up -d
```
回滚只影响前端产物，`/app/data`、`/app/recordings`、`/app/config` 为命名 bind 挂载，不在镜像内。

## 宿主机版本标记校准（发布后跟进）

发布后发现宿主机上残留一组**与线上运行版本不符**的版本标记。经核查，这些标记**不被运行中的服务
读取**，属于按文件复制方式部署时期（≤1.17.4）留下的脚手架残留，但会让下一次发布误判当前版本，
故一并校准。

### 校准前实测

| 位置 | 校准前 | 说明 |
| --- | --- | --- |

| `/opt/shn48/client/dist/index.html` | `48tools 1.17.4` | 宿主机 dist 已过期 |

### 判定依据

- 容器内 `/app/VERSION` 为镜像内自带，实测 `1.19.0`，**与宿主机 `/opt/shn48/VERSION` 无关**；
- `docker inspect` 的挂载列表只含 `config`、`runtime/{data,recordings,biliup}`，**不含 `VERSION`**；
- 宿主机 `/opt/shn48/server/index.js` 哈希 `e76c9780…` 与运行中容器 `/app/server/index.js`
  的 `333ca19e…` 不同，证明宿主机 `server/`、`client/` 目录**不是**线上运行的代码。

结论：该残留不构成线上风险，但确属版本记录不一致，予以校准。
