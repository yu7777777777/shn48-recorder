# 1.28.13 发布核对

- 发布日期：2026-10-24（北京时间）
- 触发原因：用户报告「自动录制」页显示 `Member directory HTTP 502`、监控成员名单 0 人
- 版本：1.28.12 → **1.28.13**（PATCH）
- 内容：官方成员目录不可用时改用房间名册构建名单，见 [CHANGELOG](../../CHANGELOG.md) 的 `[1.28.13]`

## 故障判定

| 检查 | 结果 |
| --- | --- |
| `h5.snh48.com/.../members.php?gid=10..70` | 7 个分团全部 **502**（宿主机与容器内一致） |
| `https://h5.snh48.com/` | 连接失败（000），只有 `http` 能握手到 nginx |
| `http://h5.snh48.com/` | 403 |
| `https://www.snh48.com/` | 200（站点本身活着，坏的是成员目录后端） |
| 房间名册 `abm48.com/api/public/snh48/room-map` | 200，含全部成员名与口袋 48 用户 ID |

结论：这是上游服务故障，旧实现把全部成员数据都押在该目录上，于是页面只能报错。上游无法由我们修复，但可以让系统在目录挂掉时仍有可用的名单。

## 修复

- 目录读取成功且非空：行为不变，按官方分团/队伍分组，名册只补缺失 ID。
- 目录整体失败或返回空集：改用房间名册构建名单，分组记为「未分组」，丢弃空名/空 ID/`0`/非数字 ID 的行。
- 目录中途部分成功：保留官方分组，不因一次抖动降级为未分组。
- 目录与名册同时不可用：仍如实报错，不返回伪空列表。
- 自动录制写入口径未变，仍只使用公开直播数据。

## 残留

1. 兜底名单没有队伍分组（全部记为「未分组」），加入监控仍可按姓名搜索添加，但按队伍筛选会退化为单一分组；官方目录恢复后自动回到完整分组。
2. 名册由第三方 `abm48.com` 提供，其字段变化会影响兜底质量；目录正常时它只用于补缺失 ID，影响面有限。
3. 上游 `h5.snh48.com` 何时恢复未知，需持续观察。
