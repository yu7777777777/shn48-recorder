# 1.27.1 发布核对：账号卡片自动生成头像

日期：2026-10-21（Asia/Shanghai）。状态：已部署原站点并核验。首次发布被隔离测试拦下，生产未受影响。

## 需求与调研

用户认为卡片只有平台占位图标「太丑」，希望后续能自动识别微博头像，并要求先看 GitHub 有无现成方案。

GitHub 检索结论（均不足以直接采用）：

- lucasjinreal/weibo_terminater（约 2.3k★）：2019 年后停更，依赖旧模拟登录。
- Xarrow/weibo-scraper（109★）：2024 年后未更新，需要登录态。
- michaelliao/sinaweibopy、CharlesPikachu/DecryptLogin 等登录库：2020–2024 停更，核心是模拟登录。
- TikHub API SDK（约 920★，2026 年仍活跃）：可返回头像，但需要注册付费 Key，第三方可见查询对象。

根因与 1.27.0 一致：生产服务器直接请求微博返回 403/432。任何绕过方式都要交出登录态或购买第三方服务，均超出用户已选定的「不保存凭据、只读公开昵称」边界。

用户选定「先做自动生成头像」。

## 实现

- 新增 monogram(account)：取昵称或账号 ID 中第一个字母或数字（跳过「-」等标点），按平台+来源做确定性哈希，映射到 6 组品牌渐变底色；应援群固定「群」。
- 卡片头像改为 40px 圆角渐变块 + 首字 + 右下角小平台标识；PlatformIcon 增加可选 className 以便复用小图标。
- 纯前端生成：不联网、不读 Cookie、不请求第三方、不新增依赖；同一账号始终同色同字，不会失效。
- 结构上保留替换位：将来若有合规头像来源，直接替换该元素即可，无需改卡片布局。
- 未伪造、未抓取微博头像；本次不新增任何登录态或付费 Key。

- 社交前端静态 + 浏览器回归 10 项全部通过。

- 候选镜像隔离测试（无网络、临时数据目录）100 项全部通过。

## 首次发布失败与恢复（如实记录）

1. 第一次发布：候选镜像隔离测试 99/100，失败项为 social.test.js「路由注册」，错误 Route.get() requires a callback function but got a [object Module]。
2. 原因：本次顺带加入的 /weibo-session 公共页面由 ESM 模块导出，index.js 用 require 取到的是 { default } 对象，Express 因此拿到非函数；该缺陷会使服务启动失败。
3. 发布脚本在镜像切换前退出，线上仍为 1.27.0、healthy；未产生任何生产变更。
4. 修正为 require("./pages/weibo-session").default；本地 app 启动与 91 项定向测试通过。
5. 第二次重跑：脚本要求发布目录不存在，而上一次已传入 tar 包并创建目录，故在归档校验处退出，仍未切换。
6. 清理：确认容器按镜像 ID 运行 1.27.0 后，删除仅由失败构建产生的坏候选镜像 shn48-shn48:1.27.1（cd446f59acd4…），并清除该次残留的 /opt/shn48-releases/1.27.1 与 /root/shn48-1.27.1.tar.gz。未执行任何无范围 prune，未删除数据、录像、配置、凭据、命名卷或任何已有回滚镜像。
7. 第三次发布：基线 64 个生产 JS 一致、隔离测试 100/100 通过后，才切换镜像。
