# 1.33.0 发布核验（版本更新检测与一键更新机制）

发布日期：2026-11-14。发布方式：**仓库驱动**（GitHub `main` @ `ed3c5ba` → 服务器 `scripts/update-from-repo.sh`），「新版本检测 + 人工确认一键更新」机制的首次实机使用。

## 功能内容

- 新增 `server/modules/update-checker/`：定时（默认 6 小时）调用 GitHub Contents API 读取仓库 `app/VERSION` 与运行版本比对；发现更新经既有通知系统推送「新版本可用」（每版本一次，状态持久化防重复提醒）。
- 新增管理端「版本更新」页（`/admin/update`）与 `/api/admin/update`（settings GET/PUT、立即检查 POST）；GitHub fine-grained PAT 仅存数据目录，接口只回显 `tokenSet`，支持清除。
- 新增 `scripts/update-from-repo.sh`：预检（root/健康/活动任务/磁盘）→ Deploy Key 浅克隆 → 版本前进校验 → **克隆源码完整性核验**（SHA256SUMS，存在性过滤）→ docker build（基础镜像 ECR 兜底、pip 走阿里云源）→ **从构建镜像导出运行时预期清单** → compose 备份与切换 → healthy 等待 → 健康接口版本核验 → 运行文件哈希核验 → 构建缓存回收。任一失败自动回滚 compose 与旧镜像。
- 通知事件新增 `update_available`（默认开启），`NotifySettings` 页事件开关同步。

## 测试与质量闸门

- `server/test/update-checker.test.js` 7 项全过（配置校验/掩码/版本比对/去重提醒/失败记录/状态持久化）。
- 全量后端回归：除 3 项已知本地环境性失败（replay-recovery / room-voice / srt，本地无 ffmpeg）外全部通过，无新增失败。
- 前端构建通过；发布清单 473 源码 / 269 运行时哈希。
- 全仓行尾统一为 LF（原生 node 转换 69 个混合行尾文件；此前 MSYS 工具文本模式使 sed/grep 转换成为空操作），加 `.gitattributes`（`* text=auto eol=lf`）；已验证 HEAD blob 与工作区逐字节一致（否则服务器克隆与清单必不一致）。

## 首次部署：闸门与修复记录（全部由安全闸门或核验环节拦截，生产全程 healthy）

1. **活动任务闸门**：官方回放定时解码校验（`ffmpeg -f null`）运行中被拦截 → 闸门精确化：只读校验类任务不算占用，录制/上传类仍拦截。
2. **磁盘闸门**：可用 4G < 6G → 清理 frontend-build:1.32.4、1.32.3 回滚镜像、npm/apt 缓存、1.24 时代构建基线残留；脚本增加核验后自动回收构建缓存。
3. **基础镜像拉取**：Docker Hub 不可达 → 脚本回退 `public.ecr.aws` 公共镜像源（服务器既有 python 镜像即来自该源）。
4. **pip 阻塞**：pypi.org 直连下载 faster-whisper 卡死 15 分钟 → 构建参数补 `PIP_INDEX_URL`（阿里云 PyPI 镜像）。
5. **compose 缺失**：服务器无 `docker compose` v2 插件（仅 v1.25.0 的 `docker-compose`）→ 脚本回退 v1。此前的"切换失败-自动回滚"即由 set -e + EXIT 陷阱正确执行。
6. **运行时哈希核验**：82 项 dist 不一致 → 根因是 **vite 产物跨环境非逐字节确定**（本地 node 24 vs 容器 node 20），server 文件零差异 → 运行时预期改为从构建出的镜像导出（镜像即预期态），源码完整性改由克隆态 SHA256SUMS 核验承担。
7. **源码核验误报**：`client/dist`、`.tools` 为 git 忽略产物、不在克隆中 → 按存在性过滤，只核验 git 跟踪源码。
8. **行尾不一致**：69 个混合行尾文件致克隆哈希与清单不一致 → 原生 node 全量转 LF 并验证 blob==working。

## 后续维护注意

- 服务器构建依赖三个镜像源兜底：Debian/NPM 走阿里云、pip 走阿里云 PyPI、Docker Hub 不可达时走 public.ecr.aws——均已写入脚本。
- 服务器可用磁盘需保持 ≥6GB（脚本闸门）；录像数据增长由应用水位清理（RESERVE 8G/TARGET 12G）自持。
- vite 构建产物不做跨环境哈希断言；运行时核验一律以「构建镜像导出清单」为准。
