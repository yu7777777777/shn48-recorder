## 起因

读者看到「账号与签到设置」弹窗里同时出现：

- `每天自动签到` **已勾选**
- `已暂停：口袋48请求失败（HTTP 200，业务码 401004），请稍后重试`

询问这行报错是什么意思。排查过程中发现并修复了两个真实缺陷。

## 一、401004 是什么

`401004` 是口袋48 **业务层**返回码：HTTP 状态仍是 `200`，但 `success:false`。本项目只做透传（`account.content()` 统一转成「请稍后重试」），**没有**对它做特殊解释 —— 它既不是登录失效，也不是签到重复。

线上实测定位（均为只读探测，签到调用见下方说明）：

| 探测 | 结果 |
| --- | --- |
| `getCheckinInfo` 当前 | `200 success:true`，`{"hasCheck":true}` |
| 当日重复签到 | `400 success:false`「今日已领取，明天再来」（正常业务提示，**不是** 401004） |
| 当日真实签到 | `200 success:true`，`{"addExp":1,"addSupport":1,"addMoney":0,"days":1}` |

结论：401004 属**口袋48 侧的临时性拒绝/限流**，重试即可，无需改配置或重新登录。

> 说明：排查时为了确认接口本身是否正常，对线上账号执行了**一次**签到调用，返回 `addExp:1 addSupport:1`，即当天的签到确实完成了。这是读者的账号，属预期内的签到行为，未修改任何其他数据。

## 二、缺陷 1：失败会占用当天，导致当天再也签不上

`tick()` 在发出网络请求**之前**就把 `lastDate` 写成今天 —— 这一步本身是对的，用于防止服务重启后重复签到。但**失败分支没有回滚**：

```js
state.lastDate = day(now); state.lastResult = '正在检查'; save();   // 先占用
...
} catch (e) { state.enabled = false; ... }                        // 但没还原 lastDate
```

后果：当天重新启用自动签到后，`tick()` 里 `state.lastDate === day(now)` 的守卫判定「今天已尝试过」，**直接跳过**。界面显示「下次 10:29」，到点却什么都不发生，读者永远等不到结果。

线上证据与此吻合：`lastDate` 停在 `2026-10-18`，而 `enabled: true`、`nextAt` 指向今天 —— 两个字段不可能由同一次失败写入，说明是失败后又被重新启用，却一直没跑起来。

**修复**：进入 `tick()` 时保存 `previousDate`，失败分支回滚为原值，当天重试即可真正执行。

## 三、缺陷 2：旧报错与新状态互相矛盾

`configure()` 重新启用时不清理 `lastResult`，而前端第 385 行**无条件**渲染它。于是「已勾选」与「已暂停」并存 —— 正是读者截图里的那一幕。

**修复**：重新启用且旧文案以「已暂停」开头时清空。

## 变更范围

- `server/modules/pocket48/auto-checkin.js`：`tick()` 保存/回滚 `lastDate`；`configure()` 清理过期暂停文案。**仅此一个源文件**，其余为测试与文档。

### 新增回归用例与变异验证

`server/test/auto-checkin.test.js` 新增「失败后当天重新启用应真正签到」，在**独立子进程**中运行 —— 该模块是进程内单例，与同文件的既有用例共享内存状态会互相污染（第一版尝试因此在 `lastDate` 上串了日期）。

变异验证：临时移除 `state.lastDate = previousDate;` 回滚后，用例立刻失败并给出 `失败不应占用当天，实际 2026-09-20`；恢复后通过。说明该断言确实锁住了此缺陷。
