# 1.26.0 发布核对：社交账号表单填写便利性

日期：2026-10-21（Asia/Shanghai）。状态：已部署原站点并验证。

## 专家交接与实现范围

用户点名 UI 设计师、后端架构师和前端开发者。三位均返回实际成果；UI 提供交互建议，后端与前端分别在限定文件实现，主会话联合回归并发布。

- 成员输入接入口袋48现有目录，使用 data.list 中 memberName/groupName 提供搜索建议，保留手输、已有成员及加载失败重试；没有新增重复目录源或成员关联模型。
- 账号输入接受账号 ID/账号名或已知微博、小红书、抖音、B站主页链接。前端原样提交，由后端本地安全解析路径 ID。昵称可跳过，大小号继续写备注，不恢复分类。
- 支持单行 Enter 保存、备注换行及 Ctrl/Cmd+Enter，避免中文输入法误提交；保存中锁定、防重复提交、错误反馈定位；补充弹窗焦点循环与关闭焦点恢复。
- 移动端独立滚动、动态视口高度、输入字号及触控区域改进。
- 前端文件为 SocialAccounts.jsx、SocialAccounts.css、social-ui.test.js、social-browser.test.js；后端文件为 modules/social/accounts.js、routes/social.js、test/social.test.js，另有版本和文档更新。

## 解析与兼容边界

- 仅解析已知主页路径；不请求输入 URL、不做 DNS 查询、不展开短链，不从任意查询参数猜 ID；跨平台、作品、短链、歧义、伪装主机、端口或用户名密码链接明确拒绝。
- 查询/片段追踪参数丢弃，仅持久化 ID；不自动抓取昵称，不自动替用户切换平台。
- 同名成员仍按既有 memberName 模型关联，候选中的辅助队伍信息不等于建立成员 ID 关联。
- 新记录无大小号分类；旧 size 兼容读取，标签说明合入备注，保留原 300 字备注及不重复追加的回归。
- 原生 datalist 在不同浏览器/手机上的展示存在差异；没有宣称真实手机或读屏器验收完成。
