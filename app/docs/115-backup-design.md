# 115 归档备份实施与验收说明

日期：2026-10-20。状态：Node持久队列、权限API、Python上传worker、系统设置和归档界面已实现并部署为1.24.1；独立Linux Python3.12.11与56项哈希锁定依赖已安装，原ASR环境保留。44项Node定向回归、30项worker离线回归通过；真实二维码创建及等待状态已核验。真实账号授权和文件上传仍待用户扫码后验收，详见[发布核对](releases/1.24.1-audit.md)。

## 目标与首版范围

把服务器上已归档、停止变化的主文件直接上传115；备份不经用户电脑中转，不依赖本机MCP常驻。沿用现有归档页和系统设置，不新增菜单。默认保留本地主归档，绝不因备份成功自动删除本地文件。现有针对原始FLV/回放缓存的清理策略保持独立，不承诺所有中间片段永久保留。

建议首版支持手动、独立批量选择、失败重试、取消以及可选的新归档自动备份。自动备份初始关闭，通过真实上传验收后由用户开启；历史录像不默默全量上传。备份内容：主视频/音频文件；已有字幕、封面、脱敏归档说明作为独立附件。未生成字幕不算失败，后续生成/变更可补传；已存在附件上传失败必须显示未完整完成，不能被视频成功掩盖。

建议根目录 /48tools归档（可修改），按成员和直播日期分组，每场用稳定recording ID作唯一标识，每次内容版本独立保存。日期采用明确的Asia/Shanghai规则，目录名清洗并限制长度。远端ID均用字符串，不依赖JavaScript数值精度。

## 已核实证据与边界

- 开发前真实基线为shn48-shn48:1.23.1、healthy，系统Python3.11.2未安装p115client。现已发布1.24.1，上传使用独立/opt/backup115/bin/python（3.12.11），系统Python与ASR仍为原3.11.2；未复制既有115凭证。
- 本机已安装115适配器基于p115client；实际发行版元数据版本0.0.9.6.5.1，Requires-Python >=3.12,<4.0（不要把包内__version__简写0.0.9当完整钉选版本）。源码可确认扫码token/状态/结果、目录上传、按ID查属性入口。未确认这是官网最新版本。
- 本机库client.upload_file支持file、pid、filename、filesha1、filesize、partsize及upload_id/callback；fs.upload包装使用10MiB分片，并把普通上传/秒传响应归一化为id、parent_id、name、size、sha1。上传回调结果不是独立验证。首次上线不把“支持分片”冒充“已验证跨进程断点续传”。
- 现有MCP仅在本机有配置线索，不能当作服务器已经授权；本轮未读取Cookie文件，不复制本机登录会话。
- 官方网页抓取因网络策略不可用，本轮API证据来自本机已安装源码；实际服务器账号、风控、上传大小限制、分片恢复、带宽表现均待真实联调。

## 部署与鉴权

使用同服务器独立Python 3.12+上传worker/sidecar，固定依赖及制品哈希；不要就地升级现有Python 3.11和ASR环境。Node仍负责任务队列、权限、进度和归档状态。worker仅在内部通信，不开放公网新端口；录制文件以只读方式提供，凭据与可恢复状态写专用持久目录。依赖可获取性、Linux构建兼容及离线制品完整性须先验证，不以本机Windows虚拟环境作为Linux运行包。

在管理员受保护的系统设置中提供115扫码登录、连接检查、目录选择及注销。二维码短期有效并绑定管理员会话，轮询服务端保持token；浏览器不接收Cookie/访问令牌。凭据保存在权限受限的独立挂载文件，不进入普通配置GET响应、录像索引、队列JSON、SSE、日志、源码包或镜像。账号失效暂停队列提示重扫，不无限自动登录。更换账号/目录时，已有任务固定原目标，不把旧账号fileId当新账号备份。当前站点为公网HTTP，正式启用登录管理建议先加HTTPS或通过受控隧道访问。

## 队列和成功判据

新建独立持久队列，不能复用B站upload_queue/uploadStatus。事实源为独立jobs任务，前后端均不依赖或写入recording.backup115摘要。使用store.atomicWrite并处理异常；store.save吞写盘异常，不适合成功确认。损坏队列必须报错停止，不把损坏当空队列覆写。

状态：待授权/排队 → 计算哈希 → 上传 → 远端核验 → 已校验；旁路包括重试等待、失败、取消、源文件已变化。视频与附件各有状态。首次done不代表源文件稳定，须等待archive-processor与回放替换的质量门完成；后台扫描可补漏，不能只靠一次SSE事件。

读取服务端归档文件须限定允许根目录、realpath校验、普通文件及长度限制，客户端不能提交任意本机路径。按固定文件版本流式计算SHA1及大小，记录mtime/size/版本快照，网络前先持久化任务。上传后重新以fileId查询远端属性（禁缓存），核对目录、文件类型、大小与SHA1。元数据一致性延迟可有限重查；缺少hash只可标未完成强核验，绝不能凭文件名或上传返回值显示已校验。核验前后还要检查本地源未变化，证据成功落盘后才显示成功。

幂等键包含账号、目标目录、recording ID和内容hash；超时/重启先按remoteId与预先确定的远端版本目录回查，避免重复上传。不可仅凭标题去重。首版worker并发1；网络暂时错误有上限的指数退避，认证失效/配额/风控暂停人工处理。停止服务时停止接单、中止活动传输并持久化可恢复状态。原片改变时旧备份保留为历史，不得把旧任务成功覆盖当前新版本状态。

## 必须接入的文件锁

不能只锁录像ID，要按实际文件路径租约保护共享文件。录像删除、storage清理、retention候选删除、replay-recovery替换、分析/剪辑相关替换路径必须统一查锁，await后及最终unlink/替换前重查。等待凭据/长期重试允许显式取消后删除，避免永久占锁。任务取消或录像被删除后，晚到的上传回调不能复活录像或覆盖新状态。用户手工删除本地时，不连带删除115副本；备份审计单独保存。

## 界面与接口

系统设置增加115连接状态、扫码授权、备份根目录及新归档自动备份开关。归档卡片增加待备份/上传/核验/成功/部分失败等状态、进度、重试/取消；独立的批量选择允许已上传B站的归档参与，不复用现有封面批选限制。保留原B站状态与流程。

建议端点：/api/admin/archive-backup115/settings、/auth/*、/jobs及/recordings/:id/backup115。集合路径必须在/:id之前注册。所有端点均需管理员权限，输入字段白名单，响应DTO仅含非敏感状态，不开放通用远端执行/任意文件读取代理。

## 发布验收

先通过模拟提供方验证队列与竞态，再在服务器由用户扫码授权，用专用测试目录上传已知小文件，重新读取远端SHA1/大小，再测一场真实大录像。验证普通上传、可出现的秒传、认证失效、网络断开、远端hash不符、重启后对账、写盘失败、重复点击、取消、并发删除/清理/回放替换、附件失败和源版本变化。

没有真实115上传及独立查询校验结果，不宣称“备份已验证可用”。没有跨进程恢复验收，不宣称断点续传。没有用户授权，不复制本机Cookie或开始批量上传。通过后按新增功能版本规则发布1.24.0，保留原运行镜像和数据；发布前版本检查/相关测试/前端构建/SHA-256，发布后健康/镜像/运行哈希与限定容器清理均遵循AGENTS.md。
