### F01 · P1 · 直播搜索触发整个前端页面白屏【线上实复现】

真实复现：18:46:02 的独立浏览器页先加载到 1 张直播卡，再输入 `audit-no-match-7f3c`。捕获 `l.category.toLowerCase is not a function`，`#root` 内容长度变为 0。仅本次浏览器页受影响，不是服务端停止工作。

证据：[线上搜索记录](<audit/2026-10-23/online-search.json>)、[白屏截图](<audit/2026-10-23/online-search-crash.png>)、[前端原逻辑复现脚本](<audit/2026-10-23/web-probes.cjs#L24-L32>)。

建议验证：数字类型 1/2、任意不匹配关键词、匹配关键词、空搜索均覆盖；不能只测无直播的空状态。

### F02 · P2 · 重启前已有录制原片未被纳入重启后的归档【隔离复现】

位置：[重启状态恢复](<app/server/modules/recorder/manager.js#L14-L26>)、[同场属主关联](<app/server/modules/recorder/manager.js#L74-L87>)、[合并候选过滤](<app/server/modules/recorder/archive-processor.js#L241-L253>)。

实证：执行原 manager 和归档模块，旧属主 `failed`，新段 `sessionId=owner`，最终 FFmpeg 输入及 `sourceFiles` 都只有 `after-restart.flv`，不含重启前片段。

边界：原片仍存在，不是文件已被删除；官方回放可用时可能补全，不能声称必定上传残缺。当前测试中的“restart-shaped”状态人为使用了 `waiting_merge`，未覆盖实际恢复状态。

证据：[录制隔离脚本](<audit/2026-10-23/recorder-probes.cjs#L55-L83>)。

### F03 · P2 · 修改 AI/ASR 服务地址并保存，会把旧密钥带到新服务【隔离复现】

位置：[设置保存](<app/server/modules/analysis/settings.js#L24-L33>)、[端点绑定检查](<app/server/modules/analysis/settings.js#L72-L82>)、[设置页提交](<app/client/src/pages/AnalysisSettings.jsx#L11-L17>)、[模型请求](<app/server/modules/analysis/service.js#L105-L107>)。

证据：[后端隔离脚本](<audit/2026-10-23/backend-probes.cjs#L74-L89>)。

### F06 · P2 · 章节候选混入空值或缺字段对象，逐条容错仍整批崩溃【隔离复现】

位置：[引用预检查](<app/server/modules/analysis/insights.js#L202-L220>)。

当任一候选有数组 `evidenceIds`，预检查遍历所有候选，无保护读取 `row.evidenceIds` 和 `ids.length`。合法候选与 `null`、`{}` 或字符串混排时抛 TypeError，尚未进入逐条清洗。服务层还可能将它呈为泛化连接失败；当前内部重试版本会重复调用模型后才失败。

实证：三种混排分别抛出读取 null 的 `evidenceIds` 或 undefined 的 `length` 错误。不是正确识别并拒绝伪造引用。

证据：[后端隔离脚本](<audit/2026-10-23/backend-probes.cjs#L53-L62>)。

边界：没有声称系统可以自动证明任意自然语言语义真假；本项针对没有匹配/没有原引用却制造证据的确定性行为。

证据：[后端隔离脚本](<audit/2026-10-23/backend-probes.cjs#L63-L73>)。

### F15 · P2 · 新增内部重试吞掉 HTTP 状态及退避提示【当前本地变化后复现，线上版本未核验】

位置：[内循环次数](<app/server/modules/analysis/insights.js#L55-L56>)、[catch-all 循环](<app/server/modules/analysis/insights.js#L330-L335>)；对照 [队列重试策略](<app/server/modules/analysis/queue.js#L9-L19>)。

内部三次循环捕获所有错误，不区分格式偏差与 HTTP 401/429，也不遵循 `Retry-After`。外层队列策略看不到前两次失败，重试计数、错误分类和延迟都无法约束这两次请求。

实证：外部设置自动重试关闭、上限 0；mock 401 或 429 并带 600000ms 提示，仍立即调用 `generate` 三次。界面称“队列级”开关，并不必然意味着产品禁止任何内层格式重试；本项重点是**HTTP 不可重试状态及退避被同样吞掉**，不能只以队列开关措辞定性。

此行为来自审计期间变化后的本地源码，尚未验证运行容器是否包含它。

证据：[后端隔离脚本](<audit/2026-10-23/backend-probes.cjs#L105-L119>)。
